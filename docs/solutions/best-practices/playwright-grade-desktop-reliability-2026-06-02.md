# 将桌面操作构建为 observe-resolve-preflight-dispatch 契约

## 背景

桌面无障碍树是实时的、可变的，且因平台而异。早先观察得到的 ref 只是证据，不是原生句柄。因此，可靠的自动化必须让每个边界都显式化，并拒绝不确定性，而不是靠猜测。

## 指导

### 1. 存储前先限定观察范围

快照存储在全局命名空间或选定的会话中。显式 `--session` 优先于 `AGENT_DESKTOP_SESSION`；不存在进程级的"当前会话"。带限定符的 ref 内嵌其产生时的快照。裸 `@eN` ref 会被拒绝并返回 `INVALID_ARGS`。当选定的命名空间无匹配时，绝不搜索其他会话。

### 2. 在操作时严格重新解析

加载保存的 `RefEntry`，并在操作前重新识别实时元素。携带元素令牌（macOS）的条目通过适配器解析，由适配器负责该平台上的重新识别。其他所有条目都在核心（`resolve_saved_ref`）中依据其捕获证明解析：捕获时它必须在其窗口的一次完整读取中唯一，且当前必须恰好有一个实时元素匹配其角色、原生 id、稳定名称和描述。零匹配为 `STALE_REF`；两个或更多，或从未被证明唯一的 ref，为 `AMBIGUOUS_TARGET`。可变值、几何和路径永远不是身份；适配器只负责落地核心选定的元素，核心再复核落地结果。

### 3. 将可操作性与派发分离

Ref 操作使用共享的自动等待和实时可操作性检查。每个命令拥有其最严格的基础交互策略：ref 操作（包括输入）以无头模式启动，而显式的 ref 定向按键保留其焦点回退。有头模式是可选启用的策略升级，不是不同的解析路径。预检失败必须说明原因并保持重试安全。

在 macOS 上，无头自然输入命令使用语义无障碍投递。有头的 `click`、`right-click`、`type`、`clear` 和 `scroll` 优先物理投递；仅语义命令保持语义。双击、三击、悬停和拖拽仅限物理投递，无有头权限时失败关闭。结果暴露实际投递的步骤机制，因此测试和调用方可以验证这一区分，而不是从成功响应中推断。

指针命令是独立的物理族。它们解析实时点，验证可见性、几何稳定性和命中测试接收，然后在派发前要求显式的光标移动策略。其终止错误不会被静默转换为重试。

### 4. 如实追踪投递

每个适配器错误都携带结构化的投递语义。如果物理操作已开始，错误不得声称可安全重试。多步输入拥有其清理守卫，并报告已知的最佳最终状态。追踪失败属于可观测性失败；它们不得改变操作是否已投递。

绝不将用户或应用提供的原始值插入可能到达追踪接收端的错误消息。改为报告形状：字符数、角色或有界枚举。原始值只有在位于 `SENSITIVE_KEYS` 匹配的键下，或已被归约为形状时，才可安全放入 `details`。脱敏规则位于 `crates/core/src/trace/trace_sanitize.rs` 中的 `sanitize_trace_value`。

### 5. 让每种传输都遵循同一核心契约

CLI、批处理和高级 FFI ref 操作共享相同的严格解析、策略升级、可操作性和信封语义。`ad_execute_by_ref` 及其超时变体运行该核心命令路径。将 CLI 命令的新语言绑定等价物路由到高级路径，并同时测试有头和无头输入下的观察效果和报告的机制。

`ad_execute_action` 和 `ad_execute_action_with_policy` 是刻意设计的较低层逃生舱。它们作用于调用方持有的原生句柄，可原样应用提供的策略，且不声称具备 RefStore 支持的 CLI 对等性。精确条目调用（`ad_resolve_element_exact`、`ad_execute_ref_action_exact_with_policy`）拒绝来自 ABI 7 的每个格式良好的条目，因为调用方构建的条目不携带捕获证明。其安全文档必须说明跳过了哪个边界：严格解析、预检或基础策略升级。ABI 结构体与已提交的 C 头文件一同进行版本化和布局固定。

### 6. 在三个层面验证

使用确定性的核心测试验证身份、策略、重试和投递规则。使用 C/C++ 头文件编译和布局测试验证 FFI。使用平台自身的权限化夹具或 dogfood 门禁验证原生观察和无害交互。在 macOS 上，这是针对 SwiftUI 夹具的发布版本二进制。在 Windows 上，这是仓库内夹具窗口加上仓库控制的 dogfood 捕获。真实应用的忽略测试保护平台接缝，如窗口身份和可访问名称一致性。有头和无头夹具场景必须同时断言观察效果和报告的投递机制。

## 为何重要

最强的失败模式是对错误的实时元素看似成功。此设计让不确定性可见：调用方收到结构化的过期、歧义、策略、超时或投递未知结果，而不是尽力而为的点击。

## 预防

- 将平台中立规则放在核心；适配器只翻译原生证据。
- 在失败的边界添加回归测试，然后对适配器变更运行夹具或安全的只读原生探测。
- 命令契约变更时，文档和帮助文本在同一变更中更新。
- 不要仅为提高表面成功率而添加绕过严格解析、策略或投递记账的回退。
