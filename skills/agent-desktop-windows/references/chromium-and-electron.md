# Chromium 与 Electron 树

基于 Chromium 的应用（Electron 或浏览器）是 Windows 上得出"树为空"错误结论的最常见来源。树是真实存在的。渲染器在第一个 UIA 客户端连接后才构建它。

## 现代 Chromium 无需标志即可暴露

Chromium 138 及更高版本会向任何 UIA 客户端暴露完整的 UIA 树，无需 `--force-renderer-accessibility` 标志。无论是否带该标志，稳定后的树都相同。不要为了添加无障碍标志而重启正在运行的应用。直接连接现有内容即可。

## 首次接触内容稀疏；等待稳定

连接后的首次读取会启动渲染器的无障碍构建，因此只返回稳定后树的约十三分之一。冷启动时，稳定过程需要 10 到 25 秒。

- 给 `snapshot` 传 `--timeout-ms`，让预算覆盖稳定过程。适配器在该预算内连接、等待树稳定并重新遍历。
- 增长的树对**全新**读取可见。启动构建的客户端可能持续返回它最初看到的骨架。若稳定后某条命令仍报告树稀疏，请运行新的 snapshot，而不是在同一进程中重试。
- 渲染器标志不能免除等待稳定的需要。带该标志时，首次接触是一场竞态，返回结果从树的一小部分到几乎全部不等。

## 带边界组的稀疏树是深度效应，而非稳定问题

Chromium 将控件嵌套在一长串未命名的透传组之下，因此稳定后的树在默认 `--max-depth 10` 下可能看不到按钮、文本框或链接。深度边界处的组带有 `children_count` 和 ref，可深入查看。

当稳定后的 snapshot 有 ref 但没有可操作控件，且其边界节点带有 `children_count` 时，不要继续等待或增大 `--timeout-ms`。请增大 `--max-depth`，或用 `snapshot --root <ref>` 深入边界 ref。

## 被遮挡的窗口会无限期保持首次接触计数

被其他窗口完全遮挡的 Chromium 窗口可能在整个稳定过程中保持首次接触的节点数。启动和稳定期间，不要将其他窗口停在目标窗口上方。若计数看起来冻结在很小的数字，请将目标窗口置于前台或最小化遮挡窗口，然后重新 snapshot。

## WPF：过早读取会绑定错误的提供程序

在其自动化对等体存在之前读取 WPF 窗口的 UIA 客户端会**永久**绑定到通用 HWND 提供程序。此后该窗口报告 `ClassName HwndWrapper[...]` 且子节点为零，进程内重试无法恢复。启动后等待几秒再读取即可获得真实的树。

请取新的 snapshot，让适配器从新句柄解析。重试同一读取无法修复。启动 WPF 应用后，在首次 snapshot 前使用 `wait --event window-opened` 或短暂的 `wait`。

## 未命名 Web 内容

对**无可访问名称**的 Web 内容的 ref，由其角色加上所携带的 AutomationId 或描述来标识，且仅当该组合在你获取时于窗口内唯一、且现在仍唯一时才能解析。边界永远不是身份。对多个共享角色、AutomationId 和描述的未命名元素之一取 ref 会返回 `AMBIGUOUS_TARGET`；请使用父级边界的带界面坐标输入，或使用 CDP 客户端（`launch --cdp`）。
